Analyze your software architecture to start thinking about what kinds of programming languages, frameworks, and libraries you might need where. Some points to consider:
	•	Which environment(s) does your software run in? For example: the cloud, a microinverter, a smart home device, etc... What constraints might come with each of these?
	•	What basic kinds of software are you running: a website? an analysis toolkit? Embedded software?
	•	What software solutions do you need that you expect a lot of others need too - and expect to be able to find a existing software for that can solve your problem?
	•	Which elements of your product/project idea are relatively niche, innovative, or perhaps a part of a USP, where you expect that you will have to develop your own custom software, since you are doing something new after all?
	•	What else might you need to consider in these choices? For example: perception of a language ("boring" and stable vs. "new and shiny"), integration with 3rd party software, ability to find developers who know / want to work with this language, etc.
